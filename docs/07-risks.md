## 最该先做的三件事

1. **备份**（R4）：首次导出已完成并通过校验；下一步是建立**第二份独立副本**（异机/异介质）与定期导出机制。
2. **锁 SDK 版本**（R2）：一次改动，永久消除"上游改坏我"的可能。
3. **核对线上 schema 与 RLS**（R15、R1）：这是所有迁移设计的前提，不做就是在猜。

## 不需要现在做的

- 不要为了"工程化"拆分单文件（R3）——在密钥回填机制没解决前，拆分会显著提高发布风险。
- 不要急着建第二套后端。先让仓库成为可信的事实来源，再谈迁移。
